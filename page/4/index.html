pi agent 使用笔记

发表于 2026-09-17 更新于 2026-10-09

常用操作

操作 作用
/model 切换模型
Shift + Tab 切换模型的思考强度
/new 新开一个 session
!命令 在当前对话窗口临时运行命令，模型可以看见命令以及运行过程
!!命令 同上，但不让 AI 看见命令运行
@文件 指明要讨论的文件；也可以直接粘贴当前目录下的文件路径
/tree 进入单个 session 的对话树，可选择历史对话回退
/compact 压缩上下文

steering 与 follow-up

  • 发现 pi 理解错了意思时，直接在对话框补充信息回车，默认消息以 steering 方式注入。注入时机是 agent 执行完一轮 agent loop 之后。
  • 使用 Alt + Enter 把消息以 follow-up 方式注入：AI 会在任务完成后再查看消息，相当于排队。

命令行模式

对话树与回退

在对话框中使用 /tree 进入单个 session 的对话树，并可以选择一个历史对话进行回退；使用 summarize 选项可以让 pi 在回退后对当前对话有个大概的印象。配合 Git 工具，可以实现对话与代码的双回退。

插件

  • 遵循一个 session 一个任务原则，用 /compact 压缩上下文。
  • pi install ... -l：-l 即 local，将插件安装到项目目录下，仅对当前项目生效。（因为全局安装的话，插件都会在会话开启后占用一定的上下文空间）
  • 安装 btw 插件实现旁路对话的功能；
  • 安装 MCP 可以让 pi 具备例如调用高德地图的功能；
  • 安装 plan 插件可以让 pi 先生成计划再执行。

RPC 模式

RPC 模式让 Pi Agent 以「无头」方式运行，通过标准输入/输出（stdin/stdout）与外部程序通信，而不是在终端里显示交互界面。

代码智能体的核心问题

  1. 循环（while True）维护（而 pi agent 是双层循环）
  2. 上下文工程
  3. 工具调用

Docker 再学习

  • Docker 中创建的用户与宿主机的用户是隔离的；但如果两者的 uid 一致（对齐），那么 Docker 中创建的文件宿主机就可以正常读写，反之亦然。
  • docker-compose build 是 docker build 的再封装，两者最终构建出的镜像内容没有区别，只是 compose 方法可以在 docker-compose.yml 的 build 配置中处理命名和参数传递等。
  • 当 docker-compose.yml 里同时定义了 image 和 build 时，Compose 默认策略是先尝试从镜像仓库拉取 image 指定的镜像；拉取成功就直接用它，拉取失败才会回退到本地构建。

env 与 ENV

写法 含义
env Linux 系统里的一个可执行程序（通常在 /usr/bin/env），作用是临时设置环境变量并执行命令。
ENV Dockerfile 的一个构建指令，用来设置镜像的默认环境变量。
