FastAPI 接口测试与 MySQL 基础

发表于 2026-07-28 更新于 2026-09-26
fastapi的接口文档/docs,即可查看所有接口情况 使用命令：curl -X POST http://localhost:8080/post_data -H "Content-Type: application/json" -d '{"name":"Alice","age":25}'（遵循http请求协议格式），来可以测试post接口 使用 @ 符号读取文件 curl -X POST http://localhost:8080/test/add_user \ -H "Content-Type: application/json" \ -d @./data.json curl -iv http://localhost:8080/api/menu curl -X POST http://localhost:8080/api/login/admin -H "Content-Type: application/json" -d '{"username":"<你的管理员账号>","password":"<已脱敏>","is_admin":1}' 我在我电脑安装了mysql. mysqld will log errors to /var/log/mysql/error.log sudo systemctl status mysql //查看服务状态 sudo mysql //直接用root角色免密码登陆到mysql中 show tables/databases; //查看所有的表/所有的databases create database XXXX; //创建一个新的database CREATE DATABASE IF NOT EXISTS my_database CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci; use XXXX //改变正在使用的database SHOW CREATE TABLE XXX; //查看 建表语句 desc XXX; //查看表信息 经典的例子： CREATE TABLE users ( -- 1. 主键：每行的唯一标识，自增 user_id INT AUTO_INCREMENT PRIMARY KEY, -- 2. 非空 + 唯一：用户名必填且不能重复 username VARCHAR(50) NOT NULL UNIQUE, -- 3. 非空 + 唯一：邮箱必填且不能重复 email VARCHAR(100) NOT NULL UNIQUE, -- 4. 默认值：新用户默认为 'active' 状态 status VARCHAR(20) DEFAULT 'active', -- 5. 检查：年龄必须合理 age INT CHECK (age >= 0 AND age <= 150), -- 6. 默认时间 + 非空：记录创建时间 created_at DATETIME NOT NULL DEFAULT NOW(), ); -- 外键通常单独定义，或者在另一个表中定义 CREATE TABLE user_profiles ( profile_id INT PRIMARY KEY, user_id INT, bio TEXT, -- 外键：确保 profile 必须关联到一个有效的用户 FOREIGN KEY (user_id) REFERENCES users(user_id) ON DELETE CASCADE ); 增加，修改，删除表中的字段以及修改表的字段名 ALTER TABLE dish ADD description TEXT; ALTER TABLE dish MODIFY price DECIMAL(10,2); ALTER TABLE dish DROP description; ALTER TABLE product CHANGE COLUMN id product_id BIGINT PRIMARY KEY; 查看已有用户 SELECT User, Host FROM mysql.user; 查看某用户的权限： SHOW GRANTS FOR 'blog_user'@'localhost'; 创建用户/修改密码： CREATE/ALTER USER 'blog_user'@'localhost' IDENTIFIED BY '新密码'; 回收myblog的数据集的所有表的delete权限： REVOKE DELETE ON myblog.* FROM 'blog_user'@'localhost'; 删除用户： DROP USER 'blog_user'@'localhost'; mysql8以上的密码认证都是经过加密，因此项目如果因为加密报错，需要pip install cryptography 核心参数与最佳实践在使用连接池时，有几个配置和习惯可以直接影响程序的稳定性和性能：关键配置项参数建议说明minsize / maxsize决定了并发能力的上下限。一般的 Web 应用（如 FastAPI 配合 asyncmy）建议 minsize 设为 5，maxsize 设为 20-50，具体取决于你的数据库配置。pool_recycle非常重要。MySQL 默认会踢掉闲置 8 小时（甚至更短）的连接。设置此参数（例如 3600 秒）能让连接池定期回收并重连，避免出现 MySQL server has gone away 报错。autocommit如果你的查询以 SELECT 为主，或者每个 INSERT/UPDATE 都是独立操作，设为 True 更方便。如果要执行强一致性的多步操作，务必设为 False 并手动 await conn.commit()。 避坑指南坚持使用 async with： 无论是 pool.acquire() 还是 conn.cursor()，一定要使用 async with 上下文管理器。如果发生异常，它可以确保连接被正确归还到连接池中，否则会导致连接池耗尽（"连接泄露"）。 永远不要使用 f-string 拼接 SQL 变量：在纯 SQL 模式下，防范 SQL 注入是你自己的责任。请始终使用 %s 作为占位符，并将变量作为元组传给 cursor.execute(sql, args)。
