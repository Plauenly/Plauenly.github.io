理解单调队列（Monotonic Queue）的核心逻辑。

1. 代码实现 (C++ 版)

相比纯 C，C++ 的 std::deque（双端队列）可以让你省去所有手动维护数组指针的烦恼。

C++

2. 记住这段代码的核心逻辑：三个“规矩”

这种算法之所以高效（时间复杂度 $O(n)$），是因为它利用了一个“优胜劣汰”的逻辑。你可以把这个双端队列想象成一个“候选人名单”：

第一，存下标，不存数值

  • 为什么： 存下标既能通过 nums[i] 找到值，又能通过 i - dq.front() >= k 判断这个数是不是已经“过期”了。

第二，“比我小又比我老的，全滚” (核心逻辑)

  • 当一个新的元素 nums[i] 准备进入队列时，它会观察队尾。
  • 如果队尾的元素比 nums[i] 小，那么这个队尾元素永远不可能成为最大值了。因为 nums[i] 既比它大，又比它年轻（存活时间更长）。
  • 动作： while 循环剔除队尾所有比新元素小的下标。

第三，“过期的，请出去”

  • 队列的头部永远存着当前最强（最大）的候选人。
  • 但英雄也会迟暮，如果队首的下标距离当前位置 i 已经超过了 k 的范围，它就该退位了。
  • 动作： if 判断队首是否过期。

3. 记忆口诀（防忘指南）

如果你下次写不出来，回想这三步：

  1. 清理过期： 队首下标太老了，踢掉。
  2. 清理弱者： 只要新来的比队尾强，队尾就连续弹出（保证队列从大到小）。
  3. 加入新血： 把新下标压入队尾。
  4. 记录结果： 此时的队首就是我们要的英雄。

复杂度分析

  • 时间复杂度： $O(n)$。虽然有嵌套循环，但每个元素最多进队一次、出队一次。
  • 空间复杂度： $O(k)$。队列中最多同时存放 $k$ 个下标。

这种“单调队列”的思想在处理“找区间最值”类问题时非常通用，掌握了这套逻辑，你就不再需要死记硬背数组下标的加减法了。

2026.4.9注意

  • 字符串在拼接的过程中，实际上是一个append的过程，即”a”+”b”，读作”ab”。但是b是append到a上的，所以字串的下标0其实是’a’而不是’b’!
  • priority_queue中自定义比较函数时， （const 类型& l, const 类型& r）return true 表示 l 应该放在 r 的后面；
  • sort中自定义比较函数时， （const 类型& l, const 类型& r）return true表示 l 应该放在 r 的前面
  • 初始化priority_queue时候，要么先创建函数体对象my_cmp cmp();，要么使用{}而不是()来初始化
  • list不支持下标来访问元素，因此使用 upper_bound(), binary_search()函数的时间复杂是线性的O(n)，而不是O(logn).
  • % 运算符优先级比 + 高，因此 ocr % i+1等价于 (ocr%i)+1
