MySQL 定时事件与商家端改造

发表于 2026-08-13 更新于 2026-09-26
查看事件定义 SHOW CREATE EVENT 事件名称; 查看创建该事件的完整SQL语句 删除事件 DROP EVENT 事件名称; 永久删除该事件 临时禁用一个事件：ALTER EVENT 事件名称 DISABLE; 设计一个定时任务(事件event)： SET GLOBAL event_scheduler = ON; CREATE EVENT clean_closed_orders ON SCHEDULE EVERY 1 DAY STARTS '2026-08-13 03:00:00' DO BEGIN DELETE FROM `orders` WHERE status = -1 AND create_at < DATE_SUB(NOW(), INTERVAL 30 DAY);(还需要判断是否transaction_id的字段有值) 连接上一句的where条件 DELETE FROM `order_product` WHERE `trade_id` = %(trade_id)s; END$$ DELIMITER ; 可能有必要设置mysql的内存占用上限 正式运行前需要将数据库的mock数据清楚，并将所有自增的键重置为从1开始 mysql加锁: SELECT * FROM order_sequence WHERE merchant_id=1 FOR UPDATE; 这个语句会对merchant_id=1的行加锁，而不管merchant_id是不是主键或唯一键，所以会可能产生锁全表的情况。 INSERT INTO order_sequence (merchant_id,seq_date,current_seq) VALUES (1,'2026-08-03',1) ON DUPLICATE KEY UPDATE current_seq=current_seq+1; 这个语句会对主键或唯一键冲突的行加锁 mysql中的update与delete语句会自动加排他锁 对商家app的修改： 1.所有 接口都是 "api/shangjia"; 2.原则：允许类别category里面没有商品，但不允许商品product没有类别; 3.在删除类别时提醒商家：分类下的所有只有一个类别的商品都会被删除，请谨慎操作 4.商品 需要增加一个is_drink的字段（用来区分订单由不同的厨师处理） 5.需要给一个可以增加商品图片的方法（仅仅上传一张图片，并选择是否为封面，上传图片大小限制在10MB以内） 6. 根据后端，需要可以对每件商品分给指定的类别以及新增商品的类别 ,如下所表示 |delete| `/api/shangjia/products/{id}/doCate`| `{"category_id" : XXX}` |get| `/api/shangjia/products/{id}/doCate`| `{"category_id" : XXX}` 7. 提醒商家每天流水 在凌晨3点时候更新 做一个后厨app 只有一个界面：只展示当天已经支付但是没有完成的订单，点进去进入每个订单的详情页面（用户支付成功会触发刷新，并且），里面有一个出餐按钮（对应/api/orders/finish）点击后即可以修改订单状态并提醒顾客，即提醒对应小程序的订单详情页面（这里需要用websocket去接受消息） 找到测试文件，运行后端的main.py并测试新增的api, 继续在这个测试文件写如测试结果 在docker compose会用，并成功部署到服务器上后再用，尝试获取.env文件 要求将这两个app都编译出来形成app文件传到github/<你的仓库名>仓库里面
