MySQL 事务、锁与一致性读

发表于 2026-08-07 更新于 2026-10-09

一致性读与隔离级别

普通 SELECT 在 REPEATABLE READ（MySQL 默认）下永远只看到事务开始时的快照，这也被称为 MVCC（多版本并发控制）；而在 READ COMMITTED（Oracle 默认）下，普通 SELECT 可以看到别的事务已经提交的数据。

  • InnoDB 默认隔离级别为 REPEATABLE READ
  • 默认锁类型为 gap lock

自动更新时间戳

当这条数据的任意字段被修改时，update_time 会自动更新为修改那一刻的时间。

如果你执行 UPDATE 把某个字段改为和原来一样的值（没有实际变化），MySQL 默认不会触发更新，update_time 也不会变。

序列号生成与加锁

在 InnoDB 中这整个是一条原子操作，应用程序无法在中间插入。

执行 SELECT ... WHERE k = 2 FOR UPDATE 时，如果表中 k 最大为 1 且 k 为唯一索引，InnoDB 会锁住索引的 (1, 正无穷) 这个开区间。

前端 pay.vue 支付流程

注意事项

  1. 后端 .env 需要正确配置：WECHAT_APP_ID、WECHAT_MECHANT_ID、WECHAT_APP_PRIVATE_KEY_PATH、WECHAT_APP_PUBLIC_KEY_PATH、WECHAT_MECHANT_SERIAL_NO 必须填写正确。
  2. paySign 签名用的 appId 必须和 JSAPI 下单时用的 appId 一致，微信会校验。
  3. wx.requestPayment 的前端回调不完全可靠，正式环境建议结合后端的支付回调通知（/api/orders/act/weixin）和主动查单来确认订单状态。
