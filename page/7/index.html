Docker 与 nginx 学习笔记

发表于 2026-08-19 更新于 2026-09-26
### docker学习： sudo docker run --name some_name -e MYSQL_ROOT_PASSWORD=my-secret-pw --restart unless-stopped -d -p 80:80 --network network1/host -v ./mysql_data:/var/lib/mysql mysql:tag 以上命令创建了名字（等同于容器id的功能），给定环境变量MYSQL_ROOT_PASSWORD， -d在后台运行，加入到子网network1/直接用宿主机的网路，将宿主机的80端口映射到容器的80端口，并且制定了"只要不是手动停止容器都会自动重启"的策略, -v表示把宿主机的目录与容器内的目录进行绑定 dockerfile是镜像制作的图纸，镜像是容器的模具 可以设置每个容器里的cpu，内存，网络带宽等资源上限（cgroups） 在/etc/docker/daemon.json中设置docker的镜像源 { "registry-mirrors": [ "https://dockerhub.icu", "https://docker.m.daocloud.io", "https://docker.1panel.live", "https://hub.rat.dev", "https://docker.mirrors.ustc.edu.cn" ] } 阿里云的： { "registry-mirrors": [ "https://<你的ID>.mirror.aliyuncs.com", "https://docker.m.daocloud.io", "https://mirror.baidubce.com", "https://dockerproxy.com", "https://mirror.iscas.ac.cn", "https://huecker.io", "https://dockerhub.timeweb.cloud", "https://noohub.ru", "https://<你的ID>.mirror.aliyuncs.com" ] } 常用命令： sudo docker start/stop/create/rm(-f) 容器名字/容器id // 启/停/创建(但不运行)/删除(强制) 容器 sudo docker inspect 容器名字/容器id // 查看容器内参数 //很有用 sudo docker logs 容器名字/容器id --follow // 查看容器日志，滚动查看 sudo docker exec 容器名字/容器id linux命令 // 在容器内执行linux命令 sudo docker exec -it 容器名字/容器id /bin/sh // 进入容器内并获得一个交互式的命令行环境 docker exec -i my-mysql-container (mysql -uroot -p123456 my_database < /path/to/your/file.sql) -i表示使用宿主机的标准输入，"()"里面时要执行的linux命令， 功能是将sql文件导入到容器的mysql数据库中 cat /etc/os-release // 查看linux的发行版本 sudo docker build -t namespace/fastapi_test . // 基于当前目录下的Dockerfile构建一个镜像，名字是fastapi_test,命名空间为namespace(主要适用于要推送到dockerhub时候) DOCKER_BUILDKIT=1 sudo docker build your-image . //Dockfile有这个选项--mount=type=cache, 就必须使用该命令来启用缓存加速，要求docker18+, sudo docker network create network1 sudo docker network list sudo docker network rm network1 sudo -i //成为超级用户 命名卷挂载的好处是可以跨容器复用 sudo docker volume create mysql_data // 准备使用命名卷的挂载方式 ，名字叫mysql_data sudo docker volume inspect mysql_data // 可以查看命名卷实际的位置,可能是"/var/lib/docker/volumes/ts_mysql_data/_data" sudo docker volume rm/list apt install iproute2 // 安装可以查看ip的工具 ip addr show compose不能使用容器名字与id, 而是在docker-compose.yml文件中配置的service名。 sudo docker compose up/down/stop/start/restart -d // 运行当前目录下的"docker-compose.yaml"，-d后台运行 注意： restart 只是“重启原来的容器”；up 是“确保服务按照 compose 配置重新创建/启动”。 sudo docker compose logs -f server名 在推送到dockerhub前，需要做： docker tag my-local-image 你的用户名/仓库名:标签 // 将名为 my-local-image 的本地镜像，标记为你的 Docker Hub 仓库镜像 docker save -o image.tar my-image:tag // 将名为 my-image:tag 的镜像保存为 image.tar 文件 ### nginx学习： http协议默认端口是80，所以在不输入端口号就默认访问80端口 nginx -t // 定位nginx的配置文件所在的目录 nginx的配置文件中的server块连接的文件的根目录在 = 配置文件的所在的目录 nginx -V // 查看nginx的安装目录，从--prefix看 nginx -s reload // 重新加载，让修改过的配置文件生效 ps -ef | grep XXX // 查看进程情况 执行docker exec nginx nginx -s reload: 如果新的nginx.config有语法错误，reload 会失败，但旧的 worker 会继续用老配置运行——服务不会挂，但你改的东西没生效。 反响代理与负债均衡: 1.在监听80的server里面写入： location /api{ proxy_pass http://backs; } 2.并在外面配置这个backs: upstream backs{ ip_hash; // 确保同一个ip分配到同一个服务器上 127.0.0.1:8000 weight=3; //更多访问这个有权重的服务器 172.83.5.6:8000; ... } 示例如下 http { upstream fastapi { server fastapi:8080; } server { listen 80; location / { proxy_pass http://fastapi; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; } } } docker token: <你的 Docker 访问令牌> image_id: <已移除>
