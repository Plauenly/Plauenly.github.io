容器日志、httpx 封装与异常传播

发表于 2026-08-23 更新于 2026-09-26
docker inspect --format='{{.LogPath}}' <容器名或ID> 查看当前容器的日志输出位置：（默认在/var/lib/docker/containers/容器id 下） 日志采用的方案：用streamHandler,然后在docker-compose.yml里面配置轮转日志,如下 services: your-service: image: nginx:latest logging: driver: "json-file" # 日志驱动Docker 容器默认将 stdout/stderr 输出捕获，然后通过日志驱动决定：1.日志存储在哪里，2.如何格式化，3.是否发送到外部系统 options: # 驱动选项 max-size: "10m" # 文件最大字节 max-file: "3" # 最多保存的日志总数 compress: "true" # 消耗cpu来对轮转日志压缩与解压缩 封装httpx.AsyncClient,有重试与异常处理，日志的功能 为每个ip地址以及访问的接口进行计时 "try...except"语句快中的raise: raise 的核心作用是“抛出异常”（Throw Exception），它的使命是中断当前函数的正常执行流程，并将控制权交给"上层调用栈"中的异常处理器（即try...except语句块中）, 并且逐层向上冒泡（Propagation）：异常会一层层向上传递，直到找到 except 或者到达顶层（__main__）。 docker logs 读取的是容器的“标准输出（stdout）”和“标准错误（stderr）”流。
