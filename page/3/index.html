pi agent 使用笔记

发表于 2026-09-17 更新于 2026-09-26
### pi agent学习 使用/model来切换模型 使用快捷键shift+tab来切换模型的思考强度 使用/new新开一个session 在当前对话窗口临时运行一个命令：1. '!docker logs -f fastapi',模型可以看见我们的命令以及命令运行过程 2. '!!docker logs -f fastapi'不让ai看见命令运行 如果要指明讨论某个文件，使用@来标记要讨论的文件，或者可以粘贴在当前目录下的文件路径 当发现pi在执行过程中理解错了我们的意思，直接在对话框补充信息回车，默认消息以steering的方式注入（注入的时机是agent在执行完一轮agent loop后再注入steering消息）。 使用alt+enter将我们的消息以follow-up的方式注入（ai会在任务完成后再查看我们的消息，即排队） 使用pi -p "msg"指令，来让pi静默执行"msg"命令而不开启任何对话框，类似于pi --mode json "你的提示词"。 使用pi -c 指令，来让pi从最近的一次session继续对话；使用pi -r可以从会话记录中挑选一个会话来继续对话。 对话框中使用/tree进入单个session的对话树，并可以选择一个历史对话进行回退,使用summarize选项可以让pi在回退后对当前对话有个大概的印象。配合git工具可以实现对话与代码的双回退 遵循一个session一个任务原则，使用/compact来压缩上下文 pi install ... (-l), -l即local,将插件安装到项目目录下，仅对当前项目生效。（因为全局安装的话，插件都会在会话开启后占用一定的上下文 空间） 安装btw插件实现旁路对话的功能，安装mcp可以让pi具备例如调用高德地图的功能，安装plan插件可以让pi先生成计划再执行。 RPC 模式让 Pi Agent 以“无头”方式运行，通过 标准输入/输出（stdin/stdout） 与外部程序通信，而不是在终端里显示交互界面 代码智能体的核心问题： 1. 循环（while True）维护（而pi agent是双层循环） 2. 上下文工程 3. 工具调用 docker的再学习： 在docker中创建的用户与宿主机的用户是隔离的，但是如果两者的uid是一致（对齐的），那么docker中创建的文件宿主机就可以正常读写，反之亦然。 docker-compose build 是 docker build 的再封装，两者最终构建出的镜像内容没有区别，只是compose方法可以在docker-compose.yml文件中的build的配置中处理了命名和参数传递等。 当 docker-compose.yml 里同时定义了 image 和 build 时，Compose 默认的策略是先尝试从镜像仓库拉取 image 指定的镜像。如果拉取成功，就直接用它；如果拉取失败，才会回退到本地构建build. env 是 Linux 系统里的一个可执行程序（通常在 /usr/bin/env），它的作用是临时设置环境变量并执行命令。 ENV 是 Dockerfile 的一个构建指令，用来设置镜像的默认环境变量。 docker inspect | grep -i env
