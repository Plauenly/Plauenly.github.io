连接池：核心参数与避坑

参数 建议
minsize / maxsize 决定并发能力的上下限。一般 Web 应用（如 FastAPI + asyncmy）建议 minsize=5，maxsize=20~50，具体取决于数据库配置。
pool_recycle 非常重要。MySQL 默认会踢掉闲置 8 小时（甚至更短）的连接，设置该参数（例如 3600 秒）能让连接池定期回收并重连，避免 MySQL server has gone away。
autocommit 以 SELECT 为主、或每个 INSERT/UPDATE 都是独立操作时设为 True 更方便；要执行强一致性的多步操作则务必设为 False，并手动 await conn.commit()。

避坑指南

  • **坚持使用 async with**：无论是 pool.acquire() 还是 conn.cursor()，一定要用 async with 上下文管理器。发生异常时它能确保连接被正确归还到连接池，否则会导致连接池耗尽（连接泄露）。
  • 永远不要用 f-string 拼接 SQL 变量：在纯 SQL 模式下，防范 SQL 注入是你自己的责任。请始终使用 %s 作为占位符，并把变量作为元组传给 cursor.execute(sql, args)。
